## 2. 产品目标与使用场景

用户经常跟视频练瑜伽，希望练过课程后，能够脱离屏幕，靠一眼可识别的体式提示回忆完整练习顺序。

产品愿景：用户提供自己练过的瑜伽视频来源，网站生成对应的可爱小女孩体式序列图，可预览、下载、打印为沿瑜伽垫边缘放置的竖向贴纸。

核心定位：**熟悉课程的练习提示，不是面向零基础用户的完整教学替代品。**

当前阶段：用于展示及少量用户体验的真实 Demo，不做大规模商业系统。

最重要的成功条件：动作没有遗漏或凭空添加；顺序与原课一致；左右表达明确；插画能辨认出动作；小女孩角色统一；成品易用。

## 3. 已确认的产品与设计决定

- 网站形式，用户不使用 Skill 或 Agent 工作台。
- 面向大陆用户的 Demo 是本线程当前方向。
- 用户界面采用自然疗愈风：米白、植物绿、留白、安静舒缓。
- 必须沿用已认可的原版女孩：丸子头、淡紫上衣、鼠尾草绿长裤；不要替换成简化线条小人。
- 小女孩可爱，但手脚关系和体式轮廓应清楚。
- 主要输出为竖条，可沿瑜伽垫边缘放置；同时提供图片和 A4 分段打印。
- 保留完整课程顺序，不擅自把原版压缩成短版或重新编排课程。
- 左右提示优于 A/B，但必须根据原视频实际动作确认，不能把 A 全部替成左、B 全部替成右。
- 时间戳是回看定位，不是体式停留时长。
- **用户明确要求去掉核对页和动作编辑功能，已经执行。** 不要自行加回。
- 当前界面只有“导入视频 → 预览与打印”。未来真实生成时可加处理进度，用户不需要看到模型、密钥、任务队列或文件存储配置。
- NFC、口令音频贴纸已讨论，但用户明确暂不考虑。
- 社区、收费系统、多角色、复杂账户管理均不是首版必需。

另一线程出现过海外版本需求；本交接不含该线程源码和最终决策。不要默认本线程网站已经具备海外版本，也不要覆盖另一项目。

## 7. 已讨论但未落地的技术方向

适合小范围 Demo 的候选结构：一个网站地址，简单后端服务、持久任务记录和后台处理进程，AI API，临时私有文件存储。先少量用户、排队处理，不必一开始采用复杂分布式架构。

用户只看见：导入 → 真实处理阶段 → 结果预览/下载。

后台处理候选流程：

1. 验证来源与实际可读取性。
2. 获取适合本次测试使用的画面、音轨，抽帧并提取口令。
3. 输出结构化动作清单，含源时间、顺序、体式描述、手脚位置、左右证据、不确定项。
4. 匹配已确认的原版体式图库；缺图才生成。
5. 内部自动质量检查；不确定时重试或明确失败。
6. 程序负责编号、文字、分页、长条图片与 PDF。

AI 候选，不是最终选型：
- 大陆路线：阿里云百炼 Qwen-VL 做视频视觉理解，独立 ASR 处理老师口令；万相作为参考图生成候选。
- 海外比较候选：Gemini 视频理解，GPT Image 系列参考图生成。
- 不以模型“自报置信度”作为动作正确的唯一依据。
- 先测试原版人物一致性和姿态忠实程度，再确定绘图模型。
- 不在前端、离线 HTML、源码仓库或聊天里硬编码/收集密钥。通过部署平台的秘密配置管理。

## 9. 推荐推进顺序及验收

### 阶段 A：来源可行性（优先）

向用户解释并确认一个能实际测试的来源方案。需要的交付是“哪些来源能读、哪些不能、依赖什么”，而不是再扩充空壳界面。

验收：可展示一个真实来源的可读取片段和对应时间；不可读取时明确原因；没有假造动作。

### 阶段 B：动作提取验证

先用短片段跑通，再测完整 20 分钟课程。结合画面和口令检查顺序、重复、换侧。输出实际调用耗时、输入输出用量及费用。

验收：逐项对照实际视频验证，记录漏动作、错序、左右不确定等问题；未通过不进入自动对外生成。

### 阶段 C：插画与成品闭环

优先复用原版女孩。缺图以原版角色和真实动作关键帧为参考生成，再做内部检查。绘图不负责整页文字排版。

验收：预览和导出的动作、顺序一致；人物无裁切；左右有依据；长条和 A4 文件可打开、可打印；失败不会返回无关示例。

### 阶段 D：小范围在线体验

在费用、账号、部署区域、访问方式和视频保留时间确认后部署。添加最低限度的体验准入、用量限制、任务隔离、文件到期删除及重启恢复。

验收：至少用两三位大陆体验者的实际网络测试打开、提交、等待、返回结果、下载全过程；用户看不到其他人的文件；API Key 不暴露；后台失败后可恢复或清楚告知。

### 后续再考虑

平台扩展、更多体式、图库维护流程、手机友好的成品查看、商业化与规模化。用户在另一次讨论中指出手机看 PDF 不方便，这也是成品使用方式的待验证问题，不能擅自认为只输出 PDF 已解决。
