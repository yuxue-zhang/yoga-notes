# 识别失败原因初步定位

2026-10-18：使用 FFmpeg 解码实际文件，每 3 秒抽取一张，共 18 张，联系表见 contact-sheet.jpg。之前浏览器生成的联系表重复显示首帧，不能作为视频内容依据；以 FFmpeg 输出为准。

结论：不能凭一个视频和两次不同提示词的调用判断模型整体不适合。

1. 测试输入为 Wikimedia 的 240p 转码，原片仅 384×288；人物、手部细节小，衣服宽松，部分镜头遮挡或切换。适合检查主轮廓，不适合验证精确手指、前后腿和左右。低清并不能解释所有错误。
2. 第一轮提示包含图库名称，模型明显产生名称与描述矛盾，属接入流程问题。已取消图库诱导，自动结果暂不按名称直接套图。
3. 模型确实产生视频内容错误：第一轮 16 秒声称双脚并拢前屈，但约 16.5 秒实际仍是双手撑地的弓步过渡；约 22.5 秒身体后弯双臂支撑，应进一步区分上犬与眼镜蛇，不能只叫“俯卧伸展”就匹配图片。
4. 第二轮只保存了拒绝状态，未保存原始提取详情，因此不能把“存在未确认内容”当成准确率数据。已补充失败诊断保留，后续以漏动作、错序、左右、姿态细节分别评估。

建议实验：先换清晰、固定镜头、人物全身可见的公开授权短片，保持 qwen3-vl-plus 和新提示词不变。建立逐项对照表后，再将同一输入与另一个经用户确认免费额度的模型比较；不能同时换视频和模型后声称找到原因。当前不新增付费或其他模型调用。
